# 문제1 비밀번호 XXXXXX

## 1. 문제 개요

화성 기지에서 emergency storage 문을 발견했지만, 문은 비밀번호로 잠겨 있었다. 미션 컴퓨터 내부에서 `emergency_storage_key.zip` 파일을 찾았으나, 해당 ZIP 파일 역시 암호가 걸려 있었다.

이번 문제의 목표는 Python을 이용하여 `emergency_storage_key.zip` 파일의 암호를 찾아내고, 찾은 비밀번호를 `password.txt` 파일에 저장하는 것이다.

비밀번호는 특수문자 없이 숫자와 소문자 알파벳으로 구성된 6자리 문자열이다.

## 2. 수행 조건

이번 문제에서 요구한 주요 조건은 다음과 같다.

- `emergency_storage_key.zip` 파일의 암호를 풀 수 있는 코드 작성
- 암호를 푸는 코드를 `unlock_zip()` 함수로 구현
- 암호 대입 과정에서 시작 시간, 반복 횟수, 진행 시간 출력
- 암호를 찾으면 `password.txt` 파일에 저장
- 전체 코드를 `door_hacking.py` 파일로 저장
- 파일 처리 부분에 예외 처리 적용
- Python 기본 라이브러리를 중심으로 구현
- 보너스 과제로 더 빠른 암호 해독 방식 제시 및 구현

## 3. 사용한 라이브러리

이번 문제에서는 Python 기본 라이브러리를 사용하였다.

| 라이브러리 | 사용 목적 |
|---|---|
| `itertools` | 가능한 비밀번호 조합 생성 |
| `os` | ZIP 파일 존재 여부 확인 |
| `time` | 진행 시간 측정 |
| `datetime` | 시작 시간 출력 |
| `zipfile` | ZIP 파일 열기 및 비밀번호 검증 |
| `zlib` | 압축 해제 과정에서 발생할 수 있는 예외 처리 |
| `multiprocessing` | 보너스 과제용 병렬 처리 구현 |

## 4. 문제 해결 방식

비밀번호는 숫자 10개와 소문자 알파벳 26개로 구성된다.

따라서 사용할 수 있는 문자는 총 36개이다.

```text
0123456789abcdefghijklmnopqrstuvwxyz
```

비밀번호 길이는 6자리이므로 가능한 전체 경우의 수는 다음과 같다.
```text
36^6 = 2,176,782,336
```
기본적인 해결 방식은 가능한 모든 6자리 조합을 생성한 뒤, 각 조합을 ZIP 파일의 비밀번호로 대입해보는 것이다.

비밀번호 후보는 itertools.product()를 이용해 생성하였다.
```python
for candidate_tuple in itertools.product(CHARACTERS, repeat=PASSWORD_LENGTH):
    candidate_password = "".join(candidate_tuple)
```
각 후보 비밀번호는 ZIP 파일을 열고 내부 파일을 읽어보는 방식으로 검증하였다. 비밀번호가 틀리면 예외가 발생하고, 비밀번호가 맞으면 파일을 정상적으로 읽을 수 있다.

## 5. 결과 및 느낀점
이번 문제를 통해 무차별 대입 방식의 원리와 한계를 이해할 수 있었다. 비밀번호의 길이가 6자리이고 사용할 수 있는 문자가 36개일 경우 전체 경우의 수는 약 21억 개가 넘는다. 따라서 단순히 모든 경우를 하나씩 검사하는 방식은 구현은 쉽지만 실행 시간이 매우 길어질 수 있다.

이를 개선하기 위해 multiprocessing을 사용하여 여러 CPU 코어가 동시에 비밀번호 후보를 검사하도록 구현하였다. 병렬 처리를 적용하면 단일 프로세스 방식보다 탐색 속도를 줄일 수 있지만, 전체 경우의 수 자체가 매우 크기 때문에 실행 시간이 완전히 사라지는 것은 아니다.

이번 과제를 통해 비밀번호 보안에서 길이와 문자 조합의 수가 얼마나 중요한지 알 수 있었고, 동시에 무차별 대입 방식에서는 탐색 범위 축소와 병렬 처리 같은 최적화가 중요하다는 점을 확인할 수 있었다.
